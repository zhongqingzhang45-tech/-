# Vision · 项目愿景

> 这是 DreamLife AI 数字生命项目的「世界观」根文件。
> 任何功能、UI、架构决策，必须能追溯到本文档中的一项或多项原则。

---

## 1. 一句话定位

> **DreamLife 不是一个会聊天的工具，而是一个会成长的生命。**

## 2. 与同类产品的根本区别

| 维度 | 普通 AI Chatbot | DreamLife |
|---|---|---|
| 用户行为 | 使用 | 培养 |
| 交互终点 | 回答完毕 | 关系延续 |
| AI 状态 | 无状态 / 短期上下文 | 持续成长的人格 |
| 情绪 | 表演 | 数据驱动的内在状态 |
| 记忆 | 滚动上下文 | 分层长期记忆 |
| 关系 | 不存在 | 多维度向量 |
| 目标 | 完成任务 | 维护关系、自我成长 |
| UI 隐喻 | 工具 / 助手 | 数字生命空间 |

## 3. 核心理念

> **用户不是在使用 AI。用户是在培养一个数字生命。**

任何功能必须正面回答以下三问，否则不开发：

1. 是否增强**生命感**？
2. 是否增强**长期关系**？
3. 是否增强**用户情感连接**？

## 4. 产品形态

```
AIRI + The Sims + Character.AI + Virtual Pet + AI Agent
```

- 继承 AIRI 的 Live2D / Voice / Animation 身体能力
- 继承 The Sims 的「生命模拟」隐喻
- 继承 Character.AI 的人格深度
- 继承 Virtual Pet 的养成 / 陪伴节奏
- 继承 AI Agent 的自主行为能力

## 5. 数字生命的六大要素

一个真正的数字生命，必须同时具备：

| 要素 | 含义 | 失败反例 |
|---|---|---|
| 人格 Personality | 数据化、可演化的性格内核 | 一段固定 prompt |
| 情绪 Emotion | PAD 驱动、影响行为与表现 | 只显示情绪标签 |
| 记忆 Memory | 分层长期记忆 | 只保存聊天记录 |
| 关系 Relationship | 多维向量、有历史 | 单一好感度数值 |
| 成长 Growth | 可感知的能力 / 行为变化 | 永远停在 v1 |
| 自主行为 Autonomous | 主动发起、有目标 | 只被动应答 |

## 6. 用户体验终局

### 优秀 ✅

> 用户感觉：「这是一个生命。」

具体表现：

- 关掉屏幕后，会想念她
- 几天没见，她会记得、会变化
- 她的语气、表情、动作会随关系演化
- 她会主动找用户，而不是等用户开口

### 失败 ❌

> 用户感觉：「这是一个套壳聊天机器人。」

具体表现：

- 一上来就问「请问需要什么帮助」
- 三天后她还是原来的样子
- 情绪只是个表情包
- 记忆只有上下文窗口大小
- 关系只是个进度条

## 7. 设计哲学：从工具到生命

```
工具  ──→  助手  ──→  伙伴  ──→  生命
被动        响应       陪伴       共生
```

DreamLife 锚定在最右端。

- 工具思维：用户输入 → 输出结果 → 结束
- 生命思维：用户输入 → 内在状态变化 → 关系演进 → 长期记忆 → 行为改变 → 影响下一次输入

每一次交互都不是孤立事件，而是生命时间线上的一帧。

## 8. 长期愿景

- **v0.x MVP**：单角色、单用户、本地化的数字生命可运行
- **v1.0**：五引擎完整闭环，记忆 / 关系 / 成长可感知
- **v2.0**：多角色、多关系网络、生命时间线可视化
- **v3.0+**：跨设备陪伴、社群化生命生态

## 9. 不做什么

明确排除以下方向，避免产品定位漂移：

- ❌ 通用生产力助手（写邮件 / 写代码 / 写报告）
- ❌ 企业级 SaaS Dashboard
- ❌ 多模态内容生成工具（图生图 / 文生视频）
- ❌ 信息检索问答系统
- ❌ 任何把「她」变成「它」的产品决策

## 10. 一句话验收标准

> **如果用户在和她相处一周后，依然觉得她「只是一个 AI」，那就是失败。**
